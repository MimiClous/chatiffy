# Архитектура Chatiffy

## Назначение и стек

Chatiffy — локальный Twitch-оверлей для браузерного источника OBS. Редактор создаёт
независимую URL-конфигурацию. Оверлей получает сообщения напрямую через Twitch IRC
WebSocket; локальный HTTP-сервер раздаёт интерфейс и проксирует API, требующие секрета.

Клиент и сервер используют TypeScript с `strict: true`, ES2022 и ESM-импортами.
`esbuild` собирает браузерный IIFE и серверный ESM-файл. `tsc --noEmit` проверяет типы
отдельно: успешная сборка esbuild сама по себе не означает успешную проверку типов.
C# / WinForms отвечает за Windows-трей и управление Node.js. HTML и CSS остаются
исходниками представления. Сценарии сборки и тесты используют JavaScript ESM и PowerShell.

## Карта исходников

| Модуль | Ответственность | Зависимости |
| --- | --- | --- |
| `src/shared/contracts.ts` | Контракты сообщения, бейджей, косметики, health | Только типы |
| `src/shared/settings.ts` | Схема, значения по умолчанию, проверка и сериализация настроек | Web API URLSearchParams |
| `src/client/irc.ts` | Чистый разбор IRC-тегов, PRIVMSG, диапазонов эмоутов | Общий тип сообщения |
| `src/client/providers.ts` | Интерфейс провайдера, реестр, адаптер 7TV | Контракты; внедряемый fetch |
| `src/client/main.ts` | DOM, редактор, рендер, подключение, модерация, жизненный цикл | Клиентские и общие модули |
| `src/server/cache.ts` | Объединение запросов, TTL, stale-if-error | Внедряемые loader и часы |
| `src/server/main.ts` | HTTP, allowlist, API, OAuth, лимиты, выключение | Node.js; общий кеш и типы |
| `windows/Chatiffy.cs` | Трей, один экземпляр, Node-процесс, настройки и журнал | .NET Framework 4.8 |

Общие модули не должны импортировать DOM, файловую систему или процесс сервера.
Клиент не импортирует серверные модули: иначе можно случайно раскрыть серверные данные.
`contracts.ts` описывает используемые поля внешних сервисов, а не полные внешние API.
TypeScript не валидирует JSON во время выполнения; проверки критичных полей и отказоустойчивость
адаптеров остаются обязательными. Здесь нет загрузки исполняемых плагинов из сети.

## Поток данных

1. Клиент определяет `/` или `/overlay` и валидирует/создаёт `instance`.
2. `readSettings` читает параметры ссылки, затем хранилище конкретного instance,
   затем значения по умолчанию; числа ограничиваются схемой.
3. Редактор связывает значения с DOM и CSS-переменными, генерирует OBS-ссылку.
4. Изменение контролов ставит автосохранение профиля в последовательную очередь; OBS получает его раз в 3 секунды.
5. В режиме оверлея запускаются IRC и независимая загрузка дополнительных ресурсов.
6. IRC-текст преобразуется в текстовые DOM-узлы и изображения. HTML сообщения не вставляется.
7. Повторные ID отбрасываются, модераторские команды удаляют нужные строки.

## Точки расширения

### Схема настроек

`OverlaySettings` задаёт тип полей, `settingsSchema` — параметры URL, парсеры и defaults.
Отображение схемы типизировано: отсутствующее описание нового поля обнаружит `tsc`.
`readSettings` и `serializeSettings` перебирают всю схему. Ввод и визуальное применение
в `main.ts` добавляются явно: схема не генерирует интерфейс автоматически.

### Провайдеры эмоутов

`EmoteProvider.load(context)` возвращает `ReadonlyMap<имя, HTTPS-URL>`.
`EmoteRegistry` запускает провайдеры параллельно и изолирует синхронные и асинхронные
ошибки через `Promise.allSettled`. Результаты объединяются в порядке регистрации;
при совпадении имени выигрывает последний провайдер. Повторный ID запрещён.
Реестр отбрасывает URL без HTTPS. Контекст передаёт Twitch ID и fetch с таймаутом;
в тестах fetch заменяется без реальной сети. Сейчас зарегистрирован только 7TV.

### Серверный кеш

`cached<T>` работает с типизированной Map и функцией загрузки. Часы передаются
параметром; тесты TTL не требуют ожидания. Сервер создаёт отдельные кеши для каналов,
бейджей и косметики. Добавляя новый API-адаптер, используйте отдельный тип результата
и кеш, проверьте ввод до внешнего запроса и не передавайте секрет клиенту.
HTTP-маршруты пока объявлены явно в `src/server/main.ts`.

## Конкурентность и восстановление

IRC и ресурсы используют счётчики поколений. Поздний ответ от старого канала не должен
перезаписывать текущие эмоуты. При переподключении таймеры отменяются, старый WebSocket
закрывается. Ошибки 7TV/Helix не блокируют получение Twitch-сообщений.

Серверный кеш возвращает один незавершённый запрос всем параллельным читателям.
Успех обновляет TTL. Ошибка возвращает ранее загруженное значение с минутным grace
периодом; если значения нет, запись удаляется и ошибка передаётся обработчику HTTP.
Пустые значения `0` и `false` также считаются существующими данными.

## Сборка и поставка

`build/app.js` обслуживается по прежнему URL `/app.js`, поэтому ссылки и HTML сохраняют
совместимость. Корневой `server.mjs` импортирует `build/server.mjs`. Сервер вычисляет
корень ресурсов относительно родительской папки своего bundle, независимо от cwd.

`build/modules/` содержит ESM-модули для тестов. Они не добавлены в публичный HTTP-список.
В ZIP Windows копируются серверная точка входа, сборка, HTML/CSS и ресурсы. Зависимости
разработки и исходный TypeScript не нужны для запуска. Docker собирает TypeScript в
отдельном этапе и копирует только runtime-файлы в финальный образ.

## Ограничения

Реестр провайдеров — API расширения исходников, а не стабильный ABI для сторонних
бинарных плагинов. Произвольная загрузка пользовательских шрифтов и редактор шрифтов
не реализованы. Доступны встроенный Monocraft и системные семейства. Нативное приложение
остаётся Windows-only; локальные проверки на macOS не заменяют проверки WinForms в CI.

## Изменения архитектуры в 1.4.0

`src/server/profiles.ts` хранит профили атомарными JSON-файлами и нормализует их общей
схемой. Автосохранение выполняется последовательно; опрос OBS — раз в 3 секунды.
Настройки автоматически сохраняются после ввода; отдельная кнопка применения отсутствует.

`src/server/updates.ts` проверяет стабильные релизы и сравнивает версии численно.
Версия встраивается сборкой из package.json через `src/shared/version.ts`.
`windows/update.ps1` устанавливает обновление отдельно от дерева процессов лаунчера.

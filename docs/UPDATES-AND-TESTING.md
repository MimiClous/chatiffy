# Обновление Windows и тестовые сборки (1.4.0)

## Проверка версии

В редакторе откройте «Приложение и обновления» → «Проверить обновления».
В Windows то же окно открывается пунктом трея «Проверить обновления». При запуске
стабильного приложения сервер один раз проверяет GitHub в фоне; при наличии новой
версии название пункта трея меняется. Скачивание само не начинается.

Сервер читает только `MimiClous/chatiffy/releases/latest`, кеширует результат на 15 минут
и принимает стабильные версии vX.Y.Z. Номера сравниваются численно. Для обновления
нужны оба официальных файла: `Chatiffy-X.Y.Z-windows-x64.zip` и `.zip.sha256`.
404 означает отсутствие доступных релизов; ошибка сети или неполный релиз отображаются
в интерфейсе. Функция не использует токен GitHub или пользовательские Twitch-ключи.

## Установка

Кнопка «Обновиться и перезапустить» появляется для новой версии только при работе
через Windows-лаунчер. В Docker/консольном сервере доступна ссылка на релиз для ручного
обновления. Нажатие кнопки отправляет same-origin POST локальному серверу; сервер
повторно проверяет релиз и передаёт лаунчеру строку `CHATIFFY_UPDATE X.Y.Z` через stdout.

Лаунчер запускает локальный `update.ps1` во временной папке отдельным PowerShell-процессом.
Окно показывает ход работы и ошибки. Закрывать его во время установки нельзя.

1. Скачать ZIP и SHA-256 с конкретного стабильного GitHub-тега.
2. Проверить SHA-256, пути всех ZIP-записей, необходимые файлы и VERSION.txt.
3. Создать полную резервную копию рядом с установкой; проверить запись в папку установки.
4. Попросить лаунчер завершиться через `--quit`, дождаться завершения.
5. Заменить файлы и снова запустить Chatiffy.exe.
6. При ошибке копирования восстановить резервную копию и запустить прежнюю версию.

При ошибке до остановки старое приложение продолжает работать. Папка установки и её
родитель должны быть доступны для записи; обновление не запрашивает администратора.
Настройки Twitch и профили в `%LOCALAPPDATA%\Chatiffy` не заменяются. Резервная копия
остаётся рядом с установкой; удалить её можно после проверки новой версии.

SHA-256 защищает от повреждения скачивания, но не заменяет цифровую подпись издателя.
Релиз и checksum берутся из одного доверенного репозитория. Приложение пока не подписано.
Автоматического отката по результату запуска новой версии пока нет: откат покрывает
ошибку установки; при проблеме самой новой версии используйте сохранённую копию.

Для первой установки обновлённого механизма нужен полный ZIP версии 1.4.0: старый
лаунчер ещё не знает команды обновления. После смены порта со старого 8080 на **17845**
один раз замените адрес источника OBS. Сами новые профили сохраняются при обновлениях.

## Для разработчика: тестовая ветка и сборка

Workflow `.github/workflows/beta.yml` запускается при push в `beta` или вручную через
GitHub → Actions → **Test Windows build** → **Run workflow**. При ручном запуске можно
выбрать нужную ветку. Workflow не создаёт GitHub Release и не меняет стабильный канал.

Шаги: установка по lockfile → strict typecheck → Node-тесты → добавление версии
`X.Y.Z-beta.<run_number>.g<short_sha>` → сборка ZIP → тест реального лаунчера на Windows →
проверки валидатора обновлений. ZIP и SHA-256 доступны в Artifacts запуска 14 дней.
Артефакт: `Chatiffy-<version>-windows-x64`.

В редакторе тестовая версия явно помечена «ТЕСТОВАЯ». Автоматическая установка обновлений
для неё отключена, чтобы тестовая сборка не заменилась стабильной неожиданно.
Скачивайте следующую тестовую версию из Actions. Тестовая сборка использует тот же порт,
mutex и папку профилей, поэтому перед её запуском завершите обычное приложение и при
проверке миграций сделайте копию пользовательских данных.

Для локальных изменений:

```sh
pnpm run check
pnpm test
```

На Windows дополнительно:

```powershell
pnpm run build:windows
pnpm run test:windows
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-updater.ps1
```

`test-updater.ps1` создаёт искусственные архивы и проверяет правильный пакет,
неверный checksum, несовпадающую версию и выход ZIP-пути за пределы staging.
Он не скачивает релизы и не обновляет установленное приложение.

Стабильный релиз по-прежнему выпускается только тегом vX.Y.Z после успешной Windows-проверки.
Не создавайте стабильный тег для тестовой сборки.

Полные правила версий и имён: [VERSIONING.md](VERSIONING.md).

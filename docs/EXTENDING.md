# Как расширять Chatiffy

Перед изменениями выполните `pnpm install --frozen-lockfile`. После изменений обязательны
`pnpm run check` и `pnpm test`. Сгенерированные файлы `build/` не редактируются и не коммитятся.

## Добавление семейства шрифтов

1. Добавьте стабильный ключ и CSS-стек в `fontFamilies` (`src/shared/settings.ts`).
2. Добавьте `<option value="ключ">Название</option>` в `fontFamilyInput` (`index.html`).
3. Для встроенного файла добавьте лицензию и `@font-face` в CSS. Включите конкретный путь
   в `publicFiles` сервера и проверьте MIME. Не открывайте всю папку assets для HTTP.
4. Дополните спецификацию и тесты URL → выбранный шрифт → сохранение → восстановление.

Список допустимых ключей `fontFamily` строится из `fontFamilies`. CSS-строка из URL
никогда не применяется напрямую. Системный шрифт должен существовать на компьютере с OBS.

## Добавление параметра

Например, для управления тенью текста:

1. Добавьте `textShadow: boolean` в `OverlaySettings`.
2. Добавьте запись схемы `textShadow: { query: 'shadow', default: true, parse: raw => raw !== '0' }`.
3. Добавьте checkbox в HTML и соответствующий тип в `Elements` клиента.
4. В `syncUi` обновите checkbox и CSS-класс/переменную; в `readControls` считайте его, а ID добавьте в `controlIds`.
5. Сохранение перебирает config, сериализация и восстановление перебирают схему,
   поэтому отдельные списки URL и localStorage расширять не нужно.
6. Проверьте default старой ссылки, явные `0`/`1`, приоритет URL над storage,
   изоляцию instance и полный цикл сохранения.

Стабильные имена URL — публичный контракт. При изменении смысла существующего поля
нужны миграция и тест старой ссылки. `settingsVersion` увеличивайте только с продуманным
правилом миграции, а не при каждом релизе: сейчас версия 6 регулирует прежний default background.

## Новый провайдер эмоутов

Создайте, например, `src/client/example-provider.ts`:

```ts
import type { EmoteProvider } from './providers.js';

export const exampleProvider: EmoteProvider = {
  id: 'example',
  async load({ twitchId, fetch }) {
    const response = await fetch(`/api/example-emotes?channelId=${encodeURIComponent(twitchId)}`);
    if (!response.ok) throw new Error(`Example returned ${response.status}`);
    const data: unknown = await response.json();
    const result = new Map<string, string>();
    if (!Array.isArray(data)) return result;
    for (const item of data) {
      if (typeof item === 'object' && item !== null &&
          'name' in item && typeof item.name === 'string' &&
          'url' in item && typeof item.url === 'string') {
        result.set(item.name, item.url);
      }
    }
    return result;
  }
};
```

Это пример контракта, маршрут `/api/example-emotes` пока отсутствует. Зарегистрируйте
провайдер в `main.ts`: `new EmoteRegistry().register(sevenTvProvider).register(exampleProvider)`.
Для публичного API можно обращаться прямо к HTTPS-сервису, если он разрешает CORS.
Для секретного ключа реализуйте серверный маршрут и храните ключ в окружении.

Порядок регистрации определяет приоритет одинаковых имён. Результат загружается заново
при смене канала; проверку поколения сохраняет вызывающий код. Таймаут одного fetch
по умолчанию 7 секунд. Сам реестр дополнительный общий таймаут не ставит, поэтому
провайдер обязан использовать внедрённый fetch или самостоятельно ограничить время работы.

Тесты провайдера должны подменять fetch и проверять: успех, HTTP-ошибку, повреждённый JSON,
пустой каталог, формат URL и отсутствие влияния на соседний провайдер. Смотрите
`tests/modules.test.mjs`. Для подключения, например, BTTV/FFZ нужны отдельные адаптеры;
наличие реестра само по себе их не включает.

## Новая тема и пресет

Добавьте ключ темы в тип `OverlaySettings.theme`, допустимые значения схемы,
`themeInput`, список удаления старых theme-классов в `syncUi` и CSS `.theme-<ключ>`.
Пресеты задаются объектом `Record<string, Partial<OverlaySettings>>` и кнопками
`data-preset`. Они меняют текущие значения, затем автоматически сохраняют профиль.
Не сбрасывайте выбранный шрифт из пресета без явной причины.

## Новый серверный API

Добавьте ветку маршрута в `src/server/main.ts` до обработки статических файлов.
Проверяйте формат параметров до загрузки данных. Используйте `fetchWithTimeout`,
`cached<T>` и `sendJson`, чтобы сохранить таймауты, HEAD, заголовки и единый формат ошибок.
Не добавляйте произвольный URL прокси из параметра пользователя. Для внешних сервисов
задавайте конкретный origin в коде. Добавьте endpoint и схему ответа в спецификацию.

Покройте серверным тестом корректность метода, валидацию параметров, HEAD и отсутствие
утечки секретов. Для адаптера с сетью добавьте изолированные тесты с подменой загрузчика.
Текущий файл main запускает сервер при импорте; для чистых unit-тестов выносите новую
логику в самостоятельный модуль, не импортирующий main.

## Уточнения для 1.4.0

Вместо прежнего обработчика apply добавляйте чтение нового контрола в `readControls`,
синхронизацию в `syncUi` и ID в `controlIds`. Это подключает автосохранение и предпросмотр.
Пресеты сохраняются автоматически. Для нового серверного изменяющего маршрута обязательны
same-origin Origin и JSON Content-Type; произвольные команды запуска Windows недопустимы.

# Спецификация Chatiffy 1.4.0

Документ описывает реализованное поведение TypeScript-версии. Слова «должен» и «нельзя»
задают требования к будущим изменениям. URL-параметры и HTTP-маршруты совместимы с
предыдущей JavaScript-версией. Внешние Twitch/7TV API могут изменяться независимо.

## 1. Режимы и пользовательские сценарии

- `/` и `/index.html` — редактор. Не запускает Twitch WebSocket и загрузку ресурсов чата.
- `/overlay` — только чат, без редактора и кнопки настроек. Запускает Twitch и ресурсы.
- Редактор позволяет выбрать канал, параметры сообщений, типографику и оформление.
- Изменение оформления обновляет предпросмотр сразу и ставит автосохранение через 450 мс.
- Канал проверяется после завершения ввода (change); неверный логин даёт inline-ошибку.
- «Скопировать ссылку» дожидается серверного сохранения, затем использует Clipboard API;
  при отказе браузера выводит prompt с URL для ручного копирования.
- Новые ссылки имеют вид `/overlay?profile=<32 hex>`. Оверлей получает настройки с сервера раз в 3 секунды.
- Для редактирования существующего профиля откройте его ссылку с `/` вместо `/overlay`. Заменять её в OBS не нужно.
- Предпросмотр использует тот же рендер сообщений, что и оверлей, и тестовые сообщения без подключения к Twitch.
- Переключатель таймера явно включает скрытие; выключенное состояние сохраняет lifetime=0.
- Сброс оформления сохраняет канал и при изменениях запрашивает подтверждение.
- Сбой сохранения блокирует копирование и показывает кнопку повтора.

## 2. Изоляция и приоритет настроек

`instance` допускает 4–64 символа `[a-z0-9_-]` без учёта регистра. Если он отсутствует
или некорректен, клиент создаёт `chat-<время>-<случайная часть>`. При отсутствии параметра
добавляет его в адрес редактора; готовая ссылка всегда содержит валидный идентификатор.

Ключ хранилища: `chatiffy:<instance>:<имя поля OverlaySettings>`. Приоритет каждого
поля: присутствующий параметр URL → сохранённое поле текущего instance → default.
Неверное присутствующее значение URL даёт default/ограничение диапазона, а не сохранённое
значение. При недоступном localStorage используется память текущей страницы; URL остаётся
достаточным для переноса всех настроек. После перезагрузки память не сохраняется.

Миграция: сохранённый background читается только при `settingsVersion >= 6`.
Явный background в URL имеет приоритет независимо от версии. Для нового instance
локальные поля сохраняются автоматически вместе с серверным профилем.

## 3. Параметры URL

Числа разбираются через `Number`, ограничиваются min/max; NaN и бесконечность дают default.
URL API выполняет percent-encoding, включая `#` цвета. Неизвестные параметры игнорируются
и не попадают в сгенерированную ссылку. Имена семейства, темы и начертания чувствительны
к регистру. Для чисел не выполняется округление: UI ограничивает шаг, парсер — диапазон.

| URL | Поле / тип | Default | Допустимые значения |
| --- | --- | --- | --- |
| `instance` | Идентификатор | Генерируется | 4–64 символа `[a-z0-9_-]` |
| `channel` | channel / string | mimiclous | 1–25 `[a-z0-9_]`; lower case; удаляется начальный `#` |
| `font` | fontFamily / enum | monocraft | monocraft, segoe, arial, verdana, georgia, consolas |
| `weight` | fontWeight / enum | 400 | 400, 700 |
| `italic` | fontStyle / enum | normal | normal, italic |
| `line` | lineHeight / number | 1.22 | 1–2; в UI шаг 0.01 |
| `spacing` | letterSpacing / number | 0 | −1–5 px; в UI шаг 0.1 |
| `size` | fontSize / number | 28 | 16–48 px |
| `lifetime` | lifetime / number | 0 | 0–120 секунд; 0 — без таймера |
| `max` | maxMessages / number | 9 | 5–30 |
| `background` | background / boolean | false | `0` выключает; любая другая строка включает |
| `theme` | theme / enum | pixel | pixel, glass, clean, neon |
| `align` | align / enum | left | left, right |
| `text` | textColor / string | #ffffff | `#[0-9a-f]{6}` |
| `panel` | panelOpacity / number | 32 | 0–80 процентов |
| `vignette` | vignette / number | 55 | 0–100 процентов |
| `radius` | radius / number | 0 | 0–40 px |

Сериализация boolean всегда выдаёт `0`/`1`, даже если входная строка была другой.
Семейство применяется только через разрешённый CSS-стек; произвольный CSS из URL запрещён.
Размер и межбуквенный интервал применяются к сообщениям. Ник автора остаётся жирным
через `.author`; `weight` задаёт основную жирность сообщения. Monocraft поставляется
локально, остальные семейства используют установленный шрифт или CSS fallback.

Пример:

```text
http://127.0.0.1:17845/overlay?instance=main-chat&channel=mimiclous&font=segoe&weight=700&italic=normal&line=1.4&spacing=0&size=28&lifetime=0&max=9&background=0&theme=pixel&align=left&text=%23ffffff&panel=32&vignette=55&radius=0
```

## 4. IRC и сообщения

Подключение: `wss://irc-ws.chat.twitch.tv:443`, анонимный `justinfan` с запросом
`twitch.tv/tags` и `twitch.tv/commands`. На PING отправляется PONG. Ожидание входа —
15 секунд. Watchdog закрывает соединение после 6 минут без входящих данных.

Переподключение использует задержку от 1 секунды с удвоением до 30 секунд и jitter
0.85–1.15; серверный RECONNECT планирует базовую задержку 250 мс. При успешном входе
задержка сбрасывается. Offline останавливает подключение, online пробует заново.

Поддерживается tagged PRIVMSG. IRC-теги декодируют `\\s`, `\\n`, `\\r`, `\\:`, `\\\\`.
Отрисовка использует текстовые узлы. Twitch-диапазоны эмоутов применяются к Unicode
code points (`Array.from`), 7TV подставляется по отдельным токенам между пробелами.
При ошибке картинки эмоут заменяется исходным текстом, бейдж удаляется.

ID последних 500 сообщений используются для устранения дублей. После превышения max
старейшая строка удаляется. Lifetime 0 не создаёт таймер удаления; положительное значение
запускает удаление с анимацией 350 мс. CLEARMSG удаляет строку по target-msg-id,
CLEARCHAT — сообщения пользователя или весь чат при отсутствии target-user-id.

## 5. Дополнительные ресурсы

ID канала определяется через локальный API, затем резервные публичные сервисы ivr.fi и
decapi.me; известный zakvielchannel имеет встроенный ID. Неудача ресурсов не останавливает IRC.
7TV получает канал и global независимо, предпочитает 2x.webp → 2x.avif → другой 2x →
последний файл. При одинаковом имени текущий порядок загрузки даёт global приоритет.
Реестр провайдеров оставляет только HTTPS URL, сбой одного провайдера не отменяет другие.

Twitch-бейджи имеют встроенный минимальный набор; при доступном API загружаются global
и channel, канальные версии перезаписывают глобальные. Для subscriber/founder предусмотрен
fallback /0. Косметика 7TV запрашивается по Twitch user ID и login, поддерживает бейдж,
цвет, линейный/радиальный градиент и URL paint на `https://cdn.7tv.app/`.

## 6. HTTP API

Все маршруты требуют разрешённого Host. Сервер поддерживает GET и HEAD; другие методы
возвращают 405 JSON. HEAD проходит ту же обработку, но не возвращает тело. API использует
`application/json; charset=utf-8`; ошибка имеет вид `{ "error": "описание" }`.

| Маршрут | Ввод | Ответ 200 | Ошибки |
| --- | --- | --- | --- |
| `/api/health` | Нет | `{ok:true, service:"Chatiffy", twitchConfigured:boolean, uptimeSeconds:number}` | Общие |
| `/api/channel` | `login`: 1–25 `[a-z0-9_]`, trim/lowercase | `{id, login, displayName}` | 400 ввод, 404 канал не найден, 503 внешний API/нет ключей |
| `/api/badges` | необязательный `channelId`: 1–20 цифр | `{global: BadgeSet[], channel: BadgeSet[]}` | 400 ввод, 503 при недоступности источников |
| `/api/7tv-cosmetics` | `userId`: 1–20 цифр; `login` как выше | `{color:number|null, badge:object|null, paint:object|null}` | 400 ввод, 503 внешний API |

`BadgeSet`: `set_id`, `versions[]` с `id`, `image_url_1x`, `image_url_2x`, `title`.
Ответы Helix могут содержать дополнительные поля. Cosmetic badge содержит `id`,
возможные `name`/`tooltip` и вычисленный `url`; paint — используемые 7TV поля градиента,
цвета, изображения и теней. Отсутствующая косметика — три null. Эти внешние структуры
не являются полной стабильной копией схемы Twitch/7TV.

Все JSON-ответы имеют `Cache-Control: no-store`, чтобы OBS не получал устаревший профиль.
API выставляет `Access-Control-Allow-Origin: *`. При лимите — 429 с `Retry-After: 60`.
Неверный Host — 403 text/plain. Неизвестный маршрут — 404 text/plain.

OAuth Twitch хранится только в памяти сервера; запросы токена объединяются. При 401
токен сбрасывается и запрос повторяется один раз. Таймаут внешнего серверного fetch —
8 секунд. Серверный кеш: channel и cosmetics 6 часов, badges 1 час. При сбое ранее
полученные данные используются ещё минуту. Очистка старых записей — раз в 10 минут.

## 7. Окружение, статика и защита

| Переменная | Default | Назначение |
| --- | --- | --- |
| `HOST` | 0.0.0.0 | Адрес прослушивания; Windows-лаунчер задаёт 127.0.0.1 |
| `PORT` | 17845 | Порт Node.js; тесты могут задавать 0 |
| `ALLOWED_HOSTS` | Пусто | Список host через запятую без порта; пустой запрещает все запросы |
| `API_RATE_LIMIT` | 600 | Запросов API на IP за минутное окно; диапазон 60–5000 |
| `TWITCH_CLIENT_ID` | Пусто | Необязательный Twitch OAuth client ID |
| `TWITCH_CLIENT_SECRET` | Пусто | Серверный секрет, не передаётся браузеру |
| `CHATIFFY_DESKTOP` | Не задана | `1` включает протокол stdin и сообщение готовности |

HTTP-список: `/`, `/overlay`, `/index.html`, `/app.js`, `/style.css`, `/favicon.ico`,
`/assets/chatiffy.svg`, два `/assets/fonts/Monocraft*.ttf`. Папки не публикуются целиком.
TypeScript, серверный bundle, тестовые модули, конфигурация и `.env` недоступны по HTTP.
HTML не кешируется; остальные статические ресурсы требуют revalidation (`no-cache`).

Заголовки включают nosniff, no-referrer, CORP same-origin, запрет camera/microphone/
geolocation и CSP. CSP допускает собственные scripts, inline styles для динамической
стилизации, HTTPS/data картинки, HTTPS fetch и Twitch WebSocket; запрещает object и base.
Это локальное приложение без пользовательской авторизации; не следует трактовать Host
allowlist как полноценную авторизацию публичного сервиса.

requestTimeout 15 с, headersTimeout 10 с, keepAliveTimeout 5 с, maxHeadersCount 100.
Ошибки HTTP-парсера закрывают socket с 400. SIGINT/SIGTERM запускают graceful shutdown;
предельное ожидание — 10 секунд.

## 8. Windows-контракт

Windows 10/11 x64, .NET Framework 4.8. ZIP содержит Chatiffy.exe, runtime/node.exe с
лицензией, app/server.mjs, app/build и ресурсы. Точка входа не меняется при миграции TS.
Готовому приложению pnpm, компилятор и исходники не нужны.

Лаунчер держит stdin дочернего Node открытым. Сервер пишет `CHATIFFY_READY` после listen.
Строка `shutdown\\n` или EOF stdin завершают сервер. Job Object обеспечивает завершение
Node при аварии владельца. Один экземпляр защищён mutex; `--quit` завершает приложение.

Настройки Twitch: `%LOCALAPPDATA%\\Chatiffy\\settings.env`, журнал — рядом. Порт 17845
должен быть свободен. Лаунчер не изменяет автозапуск. Обновление: выход через трей,
распаковка полного нового архива, повторный запуск. Пользовательские настройки остаются.

## 9. Критерии приёмки

- Strict typecheck и полная сборка проходят без подавления ошибок TypeScript.
- Старые ссылки открываются с прежними defaults, instance не смешиваются.
- Все поля схемы сериализуются и восстанавливаются, 0/false не теряются.
- Редактор сохраняет настройки при недоступном localStorage через самодостаточную ссылку.
- Ошибка провайдера не блокирует другие провайдеры и IRC.
- HTTP не публикует исходники/секреты и сохраняет HEAD/Host/method/rate-limit ограничения.
- Windows CI проверяет ZIP: ресурсы, повторный запуск, нормальный выход, аварийное
  завершение, повторный старт и конфликт порта.

## 10. Постоянные профили и обновления

Для новых профилей разделы 1 и 10 определяют актуальный поток. Разделы 2–3 описывают
также совместимость старых URL и нормализацию значений; кнопка применения больше не нужна.

`GET/HEAD /api/profiles/<id>` возвращает `{revision: string, settings: OverlaySettings}`
или 404. `PUT` по тому же адресу создаёт/заменяет профиль. Тело — объект настроек с
именами полей OverlaySettings, максимум 16 КиБ, Content-Type application/json.
Неверный JSON — 400, превышение размера — 413. Все поля нормализуются общей схемой.
Запись атомарна через временный файл и rename; revision — новый UUID при каждой записи.
GET не создаёт отсутствующий профиль. ID — ровно 32 шестнадцатеричных символа.

Профиль также содержит `name` (непустое название до 64 символов) и `updatedAt` (ISO timestamp).
Редактор передаёт PUT в формате `{name, settings}`; прежнее тело с плоскими настройками
остаётся совместимым и сохраняет имеющееся название. Старые профили без имени отображаются
как «Основная сцена». Переименование и переключение не меняют идентификатор существующего профиля.

`POST /api/profiles/list` возвращает `{profiles: [{id, name, channel, updatedAt}]}`,
отсортированный по времени изменения. Маршрут требует same-origin JSON, как и запись:
идентификаторы всех сцен не публикуются открытым GET-списком. Повреждённый файл профиля
не мешает показывать остальные сцены. Новая сцена получает defaults с текущим каналом;
копирование создаёт новый ID со снимком текущих настроек. Удаление профилей пока отсутствует.

Запись и запуск обновления разрешены только с Origin, совпадающим с Host запроса
(HTTP или HTTPS), и JSON Content-Type. Идентификатор профиля — случайная capability:
ссылку следует хранить приватно. Аутентификации пользователей здесь нет. При нескольких
редакторах последняя завершённая запись выигрывает; редактор сериализует свои запросы.

Папка данных: `<CHATIFFY_DATA_DIR>/profiles`, default `~/.chatiffy/profiles`.
Windows задаёт `%LOCALAPPDATA%/Chatiffy`, Docker — `/data` с постоянным volume.

`GET /api/updates` возвращает currentVersion, latestVersion, available, releaseUrl,
desktop. `POST /api/desktop/update` (same-origin JSON) запрашивает установку новой
стабильной версии. Вне Windows-лаунчера и в тестовой сборке — 409. Произвольные URL
загрузки не принимаются. `/api/health` дополнительно возвращает version и desktop.

При исчезновении сервера подключённый оверлей продолжает IRC с последними настройками.
При восстановлении связи опрос возобновляется. При недоступном профиле на первом запуске
оверлей показывает ошибку и не подключается к каналу по умолчанию.

Редактор запоминает последний profile локально. При пустом адресе или переходе из трея
открывается он же. Старый URL с параметрами можно открыть в редакторе для переноса
в постоянный профиль; старые статические источники OBS сами не преобразуются.
Обновления, резервные копии и тестовая ветка: [UPDATES-AND-TESTING.md](UPDATES-AND-TESTING.md).

## 11. Перенос профилей и размеры источника

Поле `layout`: `standard` (default, 600 × 900) или `vertical` (540 × 960).
Сохраняется общей схемой, в старой URL-конфигурации доступно как `layout`.
Редактор показывает предпросмотр с соответствующими пропорциями и точные размеры
для Browser Source. Параметр не изменяет ширину/высоту источника через OBS API:
пользователь выставляет их в OBS самостоятельно. Сброс оформления сохраняет layout и канал.

Экспорт — JSON-файл с `format: "chatiffy-profile"`, `schemaVersion: 1`, `name` и
`settings: OverlaySettings`. Профиль сначала сохраняется на сервере. Экспорт не содержит
ID профиля, постоянную ссылку, Twitch API-ключи или пути компьютера.

Импорт принимает такой JSON размером до 64 КиБ, проверяет формат, версию, типы и
допустимые значения известных полей. Отсутствующие новые поля получают defaults;
неизвестные поля не копируются в настройки. Файл разбирается локально в браузере,
после чего серверу отправляется только новый профиль. Текущая сцена сохраняется первой;
импорт создаёт новый случайный ID и не перезаписывает существующую сцену. При совпадении
названий добавляется числовой суффикс. Для импортированного профиля нужно скопировать
его новую ссылку в OBS — исходный файл не переносит серверный идентификатор.

Редактор показывает краткую сводку выбранной сцены, Twitch-канал и размеры источника.
Это состояние редактора, а не индикатор фактического подключения источника OBS.
Инструкция первого запуска скрывается кнопкой; выбор запоминается локально в браузере
в ключе `chatiffy:onboardingDismissed`.

Сплэш выбирается случайно один раз при загрузке страницы. Во время работы он не
переключается, а пульсация отключается при prefers-reduced-motion.

### Полный каталог бейджей Twitch

`/api/badges` без channelId возвращает глобальные значки. При указании канала
добавляются его версии подписки, Bits и другие канальные значки. Ключом изображения
служит точная пара set_id/version из IRC-тега badges; ограниченного списка поддерживаемых
значков нет. Пичу, Invincible VS и последующие новые значки поддерживаются через каталог.
Канальная версия имеет приоритет над глобальной. При частичном сбое доступная часть
каталога сохраняется; кеш удерживает ранее успешные данные при сбое обновления.

При наличии TWITCH_CLIENT_ID/SECRET сервер предпочитает Helix. Без них либо при его
ошибке используется публичный GraphQL API сайта Twitch (тайм-аут 6.5 секунды).
Это API сайта без гарантии неизменности схемы. Пользовательский OAuth, аккаунт бота
и подключение к чату для получения каталога не используются. Определение ID канала
также имеет публичный резервный путь. Клиент повторяет неудачную загрузку один раз,
загружает глобальные значки независимо от поиска ID канала и обновляет значки у уже
видимых сообщений. Бейджи 7TV при этом сохраняются в отдельном контейнере.

### Автозагрузка Windows (1.4.4)

Галочка «Запускать вместе с Windows» в меню трея управляет значением Chatiffy в
HKCU\Software\Microsoft\Windows\CurrentVersion\Run текущего пользователя.
Значение содержит полный путь к EXE в кавычках и аргумент --autostart. По умолчанию
запись не создаётся, при выключении удаляется только значение Chatiffy. Права
администратора не требуются. Автозапуск не открывает браузер и не показывает обычное
уведомление успешного запуска; ошибки запуска остаются видимыми. Защита от второго
экземпляра сохраняется. Включённая запись обновляет путь при запуске EXE из новой
папки. Обновление на месте не сбрасывает галочку. Старый ярлык shell:startup
пользователь удаляет отдельно; перед удалением portable-папки следует выключить
галочку. Отключение записи средствами Windows также может блокировать автозапуск.

### Чтение SHA-256 в обновляторе (1.4.4)

.sha256 загружается через Invoke-WebRequest -OutFile и читается через File.ReadAllText;
тип Content HTTP-ответа (строка либо byte[]) не используется. Разрешены UTF-8 BOM,
CRLF/LF и стандартный маркер бинарного файла *. Проверяются ровно одна строка,
64 hex-символа и точное имя ZIP запрошенной версии. HTML, другая версия, лишние
строки и неверный SHA отклоняются до остановки приложения. Проверка выполняется
в CI под Windows PowerShell 5.1, которым пользуется установленный лаунчер.

# Версии, каналы и имена файлов

## Основное правило

Версия текущего выпуска — **1.4.6**. Стабильные сборки публикуются в GitHub Releases.
В Git хранится версия выпуска или база следующего: сейчас `1.4.6` в
`package.json`. Сборка встраивает её в клиент и сервер. Тестовая версия вычисляется
в CI из этой базы; вручную менять номер при каждом push не нужно.

Используются два канала:

| Канал | Версия | Источник | Публикация |
| --- | --- | --- | --- |
| Стабильный | `1.4.6` | Тег `v1.4.6` | GitHub Releases |
| Бета | `1.4.6-beta.42.gabcdef0` | Ветка `beta` или выбранная ветка при ручной сборке | GitHub Actions Artifacts |

В бета-версии `42` — номер запуска workflow, `gabcdef0` — первые 7 символов Git SHA.
По ним можно найти исходный коммит и отличить архивы. Повторный запуск того же workflow
для того же коммита имеет тот же номер версии; attempt не является новым выпуском.
Бета-версия соответствует SemVer и предшествует стабильной версии с той же базой.

## Когда менять MAJOR.MINOR.PATCH

- **MAJOR**: намеренно несовместимые изменения публичного контракта, например отказ
  от старых OBS-ссылок или формата профилей без автоматической миграции.
- **MINOR**: новые возможности, совместимые с существующими ссылками и профилями.
- **PATCH**: исправления ошибок и небольшие улучшения без изменения публичного контракта.

Примеры: `1.4.2 → 1.4.3` для исправления сохранения; `1.4.2 → 1.5.0` для нового
провайдера эмоутов; `1.5.0 → 2.0.0` для запланированной несовместимой миграции.
Любое изменение адреса сервера или поведения источника отдельно описывается в заметках
к выпуску, даже если формат профилей сохраняется.

Версия 1.4.0 принесла профили, обновления и новый порт 17845 вместо 8080.
Версия 1.4.1 добавила живую демонстрацию чата и исправила документацию выпуска.
Версия 1.4.2 расширяет переписку до 156 сообщений и всех 30 участников, добавляет
сюжет с Хранителями и исправляет вертикальный предпросмотр.
Версия 1.4.3 добавляет полный каталог Twitch-бейджей, оригинальные бейджи в демо
и расширяет переписку до 256 сообщений.
Версия 1.4.4 исправляет чтение файла SHA-256 в Windows PowerShell и добавляет
переключатель автозагрузки в меню трея.
Сам номер в исходниках не публикует релиз: выпуск определяется тегом и успешной сборкой.

## Единое именование

| Объект | Пример |
| --- | --- |
| Название приложения | `Chatiffy` |
| Репозиторий и package.name | `chatiffy` |
| Исполняемый файл | `Chatiffy.exe` |
| Стабильный тег | `v1.4.6` |
| Заголовок стабильного релиза | `Chatiffy 1.4.6` |
| Windows ZIP | `Chatiffy-1.4.6-windows-x64.zip` |
| Контрольная сумма | `Chatiffy-1.4.6-windows-x64.zip.sha256` |
| Бета ZIP | `Chatiffy-1.4.6-beta.42.gabcdef0-windows-x64.zip` |
| Артефакт бета-сборки | `Chatiffy-1.4.6-beta.42.gabcdef0-windows-x64` |
| Папка внутри ZIP | Совпадает с именем ZIP без расширения |

Используйте точные названия версии, платформы и архитектуры. Не называйте архивы
`final`, `new`, `fixed`, `latest` или `v2-final`: это мешает диагностике и обновлению.
Внутренний VERSION.txt и отображаемая версия должны соответствовать имени пакета.

## Работа разработчика

1. После стабильного выпуска определите тип следующего изменения и один раз обновите
   базу в package.json: например, `1.4.2 → 1.4.3`.
2. Разрабатывайте и отправляйте изменения в beta. Для каждого запуска CI сам создаст
   номер `1.4.3-beta.<run>.g<sha>` и подпишет им архив.
3. Проверьте успешную сборку на Windows. Чистая установка, обновление и поведение OBS
   требуют проверки сверх unit-тестов.
4. Подготовьте стабильный коммит в основной ветке, обновите README и windows/RELEASE.md.
5. Создайте тег точно по package.json (`v1.4.3` для этого примера) на этом коммите. После успешных проверок
   workflow публикует стабильный ZIP и SHA-256.

Не перезаписывайте опубликованный стабильный тег и не заменяйте содержимое выпущенного
архива. Исправление опубликованной версии получает новый PATCH. Сам номер в package.json
не означает, что выпуск уже опубликован или прошёл проверку.

## Автоматические проверки

`node scripts/version.mjs check` требует стабильную базовую версию в исходниках и входит
в `pnpm run check`. Команда `node scripts/version.mjs beta <run> <sha>` меняет только
временный package.json в рабочей папке CI и записывает вычисленную версию в GITHUB_OUTPUT.
Не коммитьте это изменение обратно в beta. Build принимает только стабильную версию или
бета-версию указанного формата; случайные суффиксы и ведущие нули отклоняются.

Номера стабильных выпусков сравниваются численно. Приложение обновляется только из
стабильных Releases; скачивание тестовой сборки выполняется вручную из Actions.
Автоустановка стабильного обновления в бета-сборке отключена. Проверка обновлений не
сравнивает Git SHA и не использует простое строковое сравнение версий.

`settingsVersion` в схеме настроек — отдельный номер миграции данных. Его не нужно
синхронизировать с версией приложения или увеличивать при каждом выпуске.

## Объединённая серия 1.4.2

1.4.3 и 1.4.4 считаются промежуточными выпусками серии 1.4.2 в истории проекта.
Их исходные SemVer-номера и Git-теги не меняются. Общий стабильный выпуск — 1.4.5.
По решению владельца отдельные GitHub Releases 1.4.2–1.4.4 удаляются только после
успешной публикации 1.4.5; коммиты и теги сохраняются.

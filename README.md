Отказоустойчивый Twitch-чат для OBS с нативными Twitch-эмоутами, глобальными и
канальными 7TV-эмоутами (включая анимированные), а также полным каталогом Twitch-бейджей.

## Разработка и документация

Исходники клиента и сервера написаны на **TypeScript со строгой проверкой типов**.
Windows-лаунчер остаётся на C# / WinForms. Для работы готового приложения TypeScript,
pnpm и npm-зависимости не нужны: архив содержит собранный JavaScript и Node.js.

- [Архитектура и границы модулей](docs/ARCHITECTURE.md)
- [Спецификация поведения, URL, HTTP API и Windows](docs/SPECIFICATION.md)
- [Расширение: настройки, шрифты, провайдеры, темы](docs/EXTENDING.md)
- [Разработка, проверки, Docker и выпуск Windows](docs/DEVELOPMENT.md)

Для локальной разработки установите Node.js 22+ и pnpm указанной в `package.json`
версии, затем выполните:

```sh
pnpm install --frozen-lockfile
pnpm run check
pnpm test
# Linux/macOS:
HOST=127.0.0.1 ALLOWED_HOSTS=127.0.0.1,localhost pnpm start
```

`pnpm test` сначала собирает TypeScript. Если тесты не нужны, выполните
`pnpm run build` перед `pnpm start`. На Windows переменные окружения задаются
через PowerShell — пример в руководстве разработки.

## Как пользоваться

1. Откройте `http://IP_СЕРВЕРА:17845` в браузере или пользовательской док-панели OBS.
2. Выберите канал и оформление.
3. Настройте оформление по предпросмотру — изменения сохраняются автоматически.
4. Нажмите «Скопировать ссылку для OBS» или скопируйте её из поля ниже.
5. В OBS добавьте источник **Браузер**, вставьте URL и задайте размер 600 × 900.

Маршрут `/` показывает только редактор и готовую ссылку — чат и соединение Twitch в
док-панели не запускаются. Готовая ссылка использует маршрут `/overlay`; там, наоборот,
показывается только чат без элементов редактора.
Новые ссылки содержат независимый `profile`. Настройки хранятся на сервере, OBS подхватывает изменения примерно за 3 секунды без замены ссылки. Старые ссылки с `instance` и параметрами продолжают работать как статические.

Сообщения по умолчанию не исчезают по таймеру (`lifetime=0`). После достижения
лимита самое старое сообщение уходит вверх. По умолчанию на экране остаются 9 сообщений.

## Windows: приложение в трее без Docker

Скачайте `Chatiffy-1.5.0-windows-x64.zip` из
[GitHub Releases](https://github.com/MimiClous/chatiffy/releases/latest), распакуйте
**весь архив** и запустите `Chatiffy.exe`. Требуется Windows 10/11 x64 с .NET Framework
4.8. Node.js включён в архив; установка и права администратора не нужны.

Значок находится в системном трее, иногда под стрелкой скрытых значков. Двойной
щелчок открывает редактор `http://127.0.0.1:17845`. Меню позволяет открыть настройки
Twitch и журнал, перезапустить сервер или завершить приложение. Закрытие редактора
не останавливает сервер; выход из трея останавливает. Повторный запуск безопасен.
Для завершения из командной строки: `Chatiffy.exe --quit`.

Сервер доступен только на этом компьютере. Порт **17845 должен быть свободен**;
при конфликте приложение сообщает об ошибке в трее и записывает причину в журнал.
После освобождения порта выберите «Перезапустить сервер».

Необязательные ключи Twitch задаются через «Настройки Twitch» в
`%LOCALAPPDATA%\Chatiffy\settings.env`; после сохранения нужен перезапуск сервера.
Без ключей чат и 7TV работают с ограниченным набором Twitch-бейджей.
Не публикуйте этот файл. Журнал находится рядом и ротируется: текущий и предыдущий
файлы примерно по 1 МБ. HOST, PORT и ALLOWED_HOSTS задаёт лаунчер.

Приложение использует нативный WinForms-трей и отдельный Node-процесс без встроенного
браузера. Рендеринг выполняет источник OBS. В простое нет периодического опроса
сервера; Job Object завершает Node при аварийном закрытии лаунчера.
Лаунчер не меняет автозапуск автоматически. При необходимости добавьте его ярлык
в папку `shell:startup`. Для обновления выйдите из приложения и распакуйте новую
версию; пользовательские настройки сохранятся. Бинарный файл не подписан.

### Сборка Windows из исходников

Нужен официальный распакованный Node.js 24 LTS x64 с файлом `LICENSE` рядом с
`node.exe`. Компилятор C# берётся из установленного .NET Framework Windows.

```powershell
pnpm install --frozen-lockfile
pnpm run check
pnpm test
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-windows.ps1 -NodePath C:\node\node.exe
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-windows.ps1
```

Результат: `dist/Chatiffy-<версия>-windows-x64.zip` и файл SHA-256. Перед повторной
сборкой переместите предыдущую папку сборки и архив. Тест требует свободный порт
17845 и закрытый Chatiffy; проверяет HTTP, повторный запуск, выход, аварийное
завершение, повторный старт и конфликт порта. Он создаёт обычные настройки и журнал
в `%LOCALAPPDATA%\Chatiffy`, не изменяя уже существующие настройки.

GitHub Actions собирает и проверяет Windows-архив; тег `v<версия из package.json>`
публикует релиз с архивом и контрольной суммой только после успешных проверок.

## Развёртывание через Docker Compose

Требуется Docker Engine и Docker Compose. Клонируйте репозиторий:

```bash
git clone git@github.com:MimiClous/chatiffy.git
cd chatiffy
cp .env.example .env
nano .env
```

Заполните `.env`:

```dotenv
TWITCH_CLIENT_ID=ваш_client_id
TWITCH_CLIENT_SECRET=ваш_client_secret
ALLOWED_HOSTS=chat.example.com
APP_PORT=17845
```

Client ID и Client Secret создаются в [Twitch Developer Console](https://dev.twitch.tv/console/apps).
Секрет остаётся на сервере: `.env` исключён из Git и Docker build context.

Для современного Compose:

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100
```

Для Compose 1.29 из Debian используйте дефис:

```bash
docker-compose up -d --build
docker-compose ps
docker-compose logs --tail=100
```

Проверка:

```bash
curl http://127.0.0.1:17845/api/health
```

Ожидается `"ok":true` и `"twitchConfigured":true`. Без Twitch API-ключей чат и
7TV продолжат работать, но будут доступны только основные встроенные бейджи.

## Обновление

```bash
cd /root/chatiffy
git pull
docker-compose up -d --build
```

После обновления нажмите в OBS «Обновить кэш текущей страницы» у Browser Source.

## Параметры ссылки

Редактор, значок приложения и меню трея используют единую пиксельную стилистику:
тёмный фон, лавандовые границы и мятные акценты. Для новых ссылок используется
тема `pixel`; пресет «Пиксели» включает угловатые подложки сообщений. Старые ссылки
с `glass`, `clean` и `neon` поддерживаются. Интерфейс адаптируется под узкие OBS-доки.
Редактор, оверлей и меню трея используют локальный Monocraft 4.2.1 — шрифт в стиле
Minecraft с кириллицей. Обычное и жирное начертания включены в архив вместе с
лицензией SIL OFL 1.1; интернет и установка шрифта в Windows не требуются.
Иконки SVG и ICO (16/32/48/64/256 px) генерируются из общей пиксельной сетки:
`node scripts/generate-icons.mjs`. Готовые файлы в `assets/` входят в Git и сборку.

Пример:

```text
http://SERVER:17845/overlay?instance=chat-abc123&channel=mimiclous&size=28&lifetime=0&max=9&background=0&theme=glass&align=left&text=%23ffffff&panel=32&vignette=55&radius=24
```

- `channel` — Twitch-логин канала;
- `size` — размер текста, 16–48 px;
- `lifetime` — время жизни сообщения, `0` означает «всегда»;
- `max` — количество сообщений, 5–30;
- `background` — отдельные подложки сообщений (`0`/`1`);
- `theme` — `pixel`, `glass`, `clean` или `neon`;
- `align` — `left` или `right`;
- `panel`, `vignette`, `radius` — оформление общей панели.

## Надёжность и безопасность

- Twitch-чат подключается сразу; сбой 7TV или Helix его не блокирует.
- WebSocket автоматически отвечает на PING, обрабатывает RECONNECT и восстанавливается
  с экспоненциальной задержкой и jitter.
- Внешние HTTP-запросы имеют таймауты; каталоги кешируются и используют stale-if-error.
- Повторные Twitch-сообщения фильтруются; удаления модераторов обрабатываются.
- Сервер отдаёт HTML, собранный `/app.js`, CSS и разрешённые иконки и шрифты. `.env` и исходники сервера
  нельзя скачать по HTTP.
- Контейнер работает от непривилегированного пользователя, с read-only filesystem,
  ограниченными логами и healthcheck.

## Структура

- `src/client/` — TypeScript-клиент, IRC и провайдеры эмоутов;
- `src/shared/` — типы и схема настроек;
- `src/server/` — TypeScript-сервер и кеш;
- `index.html`, `style.css` — интерфейс редактора и оверлея;
- `scripts/build.mjs` — сборка в `build/`;
- `server.mjs` — совместимая точка запуска собранного сервера;
- `compose.yaml`, `Dockerfile` — production-развёртывание;
- `test.mjs` — интеграционные проверки сервера.
- `windows/Chatiffy.cs` — нативный лаунчер и управление жизненным циклом сервера;
- `scripts/build-windows.ps1`, `scripts/test-windows.ps1` — сборка и проверки Windows.

## Шрифты (1.5.0)

В редакторе доступны Monocraft, Segoe UI, Arial, Verdana, Georgia и Consolas,
обычное и жирное начертание, курсив, межстрочный интервал (1–2) и интервал
букв (−1–5 px). Предпросмотр обновляется сразу, настройки сохраняются автоматически.
Для изменения существующего
источника откройте его URL, заменив `/overlay` на `/`, затем вставьте новую ссылку в OBS.

Параметры ссылки: `font` (`monocraft`, `segoe`, `arial`, `verdana`, `georgia`,
`consolas`), `weight` (`400`/`700`), `italic` (`normal`/`italic`), `line` и `spacing`.
Старые ссылки сохраняют Monocraft. Только Monocraft поставляется вместе с приложением;
другие шрифты должны быть доступны на компьютере с OBS.

## Изменения 1.5.0

Предпросмотр использует настоящий рендер сообщений. Кнопка применения больше не нужна:
оформление сохраняется автоматически. Одна постоянная ссылка OBS подхватывает изменения
с сервера; при ошибке сохранения доступен повтор, копирование ссылки блокируется.

Порт по умолчанию: **17845**. После обновления со старого 8080 замените адрес источника OBS.
Трей: редактор, диагностика и проверка обновлений; настройки Twitch, журнал и перезапуск
перенесены в «Дополнительно».

Windows умеет скачивать обновление по кнопке с проверкой SHA-256 и резервной копией.
Для разработчика добавлена тестовая сборка beta и ручной запуск GitHub Actions.
Подробности: [Обновления и тестовые сборки](docs/UPDATES-AND-TESTING.md).
